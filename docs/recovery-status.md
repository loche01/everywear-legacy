# 복구 과정

팀 프로젝트가 끝난 뒤 남아 있던 작업본들은 서로 버전이 달라, 그대로는 어느 것도 실행되지 않았습니다. 가장 완성도가 높은 작업본을 기준으로 잡고 아래 순서로 복구했습니다.

이 공개 저장소는 복구 작업용 저장소와 별도로 새 Git 기록으로 시작했습니다. 복구 초기의 세부 커밋은 여기에 포함되어 있지 않습니다.

## 1. 실행환경과 DB

- Java 21, Tomcat 9 기준으로 실행되도록 정리
- DAO 코드가 실제로 사용하는 테이블·컬럼을 기준으로 DB schema를 다시 작성 ([DB 복구](db-recovery.md))
- DB 접속 정보와 외부 서비스 키를 코드에서 빼고 환경변수로 분리
- 회원가입을 하나의 transaction으로 묶어 중간 실패 시 일부만 저장되지 않도록 수정

## 2. 로그인과 계정 보안

- 평문 비밀번호를 PBKDF2 해시로 전환. 기존 평문 계정은 로그인에 성공하면 자동으로 해시로 바뀜
- 로그인 성공 시 세션 ID 재발급, 로그인 후 이동 주소를 내부 경로로 제한
- 비밀번호 찾기·계정 잠금 해제의 본인확인을 목적별로 분리하고, 인증 결과를 한 번만 쓰도록 변경
- 로그아웃을 POST + CSRF 확인 방식으로 변경

자세한 내용은 [계정·인증 보안](auth-security.md)에 있습니다.

## 3. 데이터 변경 요청 보호

- **사용자 기능** — 장바구니, 찜, 배송지, 회원정보, Q&A, 리뷰의 변경 요청에 로그인·POST·CSRF·본인 소유 확인을 추가
- **첨부파일** — Q&A·리뷰 첨부파일의 형식·내용·크기를 검사하고, DB 저장이 실패하면 저장한 파일을 정리
- **관리자 상품** — 조회와 변경 요청을 구분하고, 변경은 POST + 관리자 CSRF로만 허용. 이미지 업로드는 실제로 이미지로 읽히는지 확인하고, 상세·이미지 저장을 하나의 transaction으로 묶음
- **관리자 공지** — 변경 요청을 보호하고 입력값을 검증. 코드에 박혀 있던 관리자 ID 기본값을 제거하고, 관리자 조회만으로 조회수가 오르던 문제와 출력 escape를 수정
- **관리자 주문·배송·환불** — 상태 변경에 transaction 적용, 주문·배송 ID가 서로 맞는지 확인, 허용된 순서로만 상태가 바뀌도록 수정

## 4. 결제

원본 코드는 브라우저가 보낸 결제 금액과 결과를 서버에서 다시 확인하지 않고 그대로 저장했습니다. 금액을 조작해도 주문이 완료되는 구조였습니다.

- **처음에는** 결제 경로 전체를 막았습니다. 주문·결제·배송 저장, 적립금 변경, 결제 후 장바구니 삭제, 문자 발송을 모두 제거하고 안내 화면으로 대체했습니다.
- **이후에는** 원본과 같은 아임포트 테스트 식별코드와 이니시스 테스트 결제창까지만 되살렸습니다. 결과는 화면에만 보여 주고 DB에는 저장하지 않습니다. 주문자 입력값은 escape하고 결제 금액은 범위를 검사합니다.

결제 결과를 실제로 저장하려면 서버에서 PG사에 결제 금액을 다시 확인하는 과정이 필요하며, 이 부분은 구현하지 않았습니다.

## 5. 공개 전 정리

- 사용하지 않는 테스트용 JSP·CSS, 개발용 SQL, 관리자 계정을 조회하던 디버그용 서블릿 제거
- 코드에 박혀 있던 OAuth redirect 주소와 개인 도메인을 환경변수로 이동
- 사용하지 않는 Windows 업로드 절대경로와 호출되지 않는 옛 코드 제거
- 설정값·테스트 데이터·개인정보가 남아 있지 않은지 확인한 뒤 새 Git 기록으로 공개

## 6. 원본 상품 데이터와 화면 복원

공개 초기에는 크롤링한 상품 데이터 대신 직접 만든 샘플 상품 24개를 넣었습니다. 이후 원래 프로젝트 모습을 그대로 보여 주기 위해 원본으로 되돌렸습니다.

- **상품 데이터** — 원본 크롤링 상품 데이터(상품 1,518 / 상세 3,513 / 이미지 7,410)를 복원하고 샘플 상품은 제거
- **화면** — 메인 영상과 이미지, 상품 목록·상세, 마이페이지, 로그인 화면을 원본 디자인으로 복원. 앞에서 넣은 보안 처리는 그대로 유지
- **Naver 로그인** — 버튼만 화면에서 뺐습니다. 서버 코드는 남겨 두어 나중에 다시 붙일 수 있습니다.

## 7. 기능 시연 중 발견해 고친 문제

샘플 데이터를 넣고 사용자·관리자 기능을 모두 실행해 보면서 다음 문제를 찾아 고쳤습니다.

| 증상 | 원인 | 조치 |
|---|---|---|
| 인증 메일이 전혀 발송되지 않음 | JavaMail 1.4.6이 Java 21에서 막힌 TLS 1.0으로 연결을 시도 | SMTP 연결에 TLS 1.2 지정 |
| 관리자 회원정보 수정 화면 500 오류 | 전화번호·마케팅 수신값이 비어 있는 회원에서 NullPointerException | null 처리 추가 |
| 관리자 상품 관리의 카테고리 목록이 비어 있음 | 원본 카테고리 데이터에 최상위 행이 없음 | 하위 카테고리 값에서 최상위 목록을 만들도록 수정 (데이터는 그대로) |
| 결제창이 열리지 않음 | 앞서 결제 경로를 안내 화면으로 대체함 | 테스트 결제창까지만 복원 (4번 참고) |
| 카카오 로그인 후 예외와 404 | 동의항목이 없을 때 응답 파싱 실패, 존재하지 않는 오류 페이지로 이동 | 안전하게 파싱하고 실패 시 로그인 화면에 안내 표시 (구글도 동일) |
| 카카오 로그인이 이메일 없이 진행되지 않음 | 카카오는 개인 개발자 앱에 이메일을 제공하지 않음 | 항상 제공되는 카카오 회원번호로 회원을 식별하도록 변경 |
